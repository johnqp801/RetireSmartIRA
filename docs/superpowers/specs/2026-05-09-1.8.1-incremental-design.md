## Per-Item Specifications

### Item #6 — ACASubsidyEngine cliff-sentinel filter

**File:** `RetireSmartIRA/ACASubsidyEngine.swift`
**Function:** `interpolateApplicableFigure(fplPercent:table:)`
**Bug:** Uses 400% FPL row (applicableFigure = 1.0 sentinel) as an interpolation endpoint, producing nonsensical values for 300-400% FPL households (e.g., 350% FPL gets ~0.54 interpolated value).
**Fix:** Filter `applicableFigure < 1.0` rows out of interpolation.
**Acceptance:**
- 350% FPL household correctly gets applicable figure of ~0.085 (or whatever the actual table caps at), not interpolated junk
- 401% FPL still triggers cliff (applicableFigure = 1.0)
- Existing ACASubsidyEngineTests still pass; add one new test `testApplicableFigure_300to400_DoesNotInterpolateThroughCliff`

### Item #7 — MedicareCostEngine MAPD Part D double-count

**File:** `RetireSmartIRA/MedicareCostEngine.swift`
**Bug:** For Medicare Advantage with drug coverage (MAPD), Part D coverage is included in the Advantage premium — but engine adds `partDBase` ($50/mo) on top, double-counting.
**Fix:** Make `partDBase` plan-type aware: returns 0 for `.medicareAdvantage`. Part D IRMAA surcharge still applies because CMS bills it separately even with MAPD.
**Acceptance:**
- MAPD plan returns annual cost = `advantagePremium × 12 + irmaaPartBSurcharge + irmaaPartDSurcharge` (no `partDBase`)
- Original Medicare unchanged
- New test `testMAPD_DoesNotDoubleCountPartDBase`

**State exemption table** (from Tim's research + supplements):
- **Fully exempt:** AL, AR, CT, HI, IA (after age 55), IL, KS, LA, ME, MA, MI, MN, MS, MO, NJ, NY (some thresholds), NC, ND, OH, OK, PA, SC, WI, AZ (since 2021), IN, NE, NM (partial), OR (partial), UT, WV

- **Fully taxed:** CA, DE (mostly), DC (after retirement age 60+), GA, ID, KY, MD, MT, RI, VT, VA

**Concrete data structure:**

```swift
struct MilitaryRetirementExemption {
    enum ExemptionLevel {
        case fullyExempt
        case partiallyExempt(percentOfIncomeTaxable: Double, ageThreshold: Int?)
        case fullyTaxable
        case noStateIncomeTax
    }

    static func exemption(for stateCode: String, age: Int) -> ExemptionLevel { ... }
}
```

**Engine integration:**
- In `calculateStateTaxFromGross()`: when iterating income sources, if type == `.militaryRetirement`, apply state exemption before adding to state taxable income
- Federal tax treatment: same as ordinary pension (taxable)

**UI:**
- Add `.militaryRetirement` to the income type picker
- Display name: "Military Retirement"
- Per-type guidance:
  > **Military Retirement Pay** is federally taxable but exempt from state income tax in ~30 states. The app uses your state of residence to compute the correct state treatment.

**Acceptance:**
- New IncomeType case present, picker shows "Military Retirement"
- Federal tax: full amount taxed at ordinary rates
- State tax for fully-exempt state (e.g., NC): excluded from state taxable income
- State tax for fully-taxed state (e.g., CA): included in state taxable income
- Tests:
  - `testMilitaryRetirement_FederalTax_TaxedAsOrdinary`
  - `testMilitaryRetirement_StateTax_FullyExemptState_NotTaxed` (NC, PA, SC, etc.)
  - `testMilitaryRetirement_StateTax_FullyTaxedState_Taxed` (CA)
  - `testMilitaryRetirement_NoStateIncomeTax_Zero` (TX, FL)
  - At least 5 states covered in tests across different exemption levels

**Effort:** 2-3 days

## Process Commitments (the new safeguards)

Per the V2.0 archaeology findings, the following process changes apply to 1.8.1 execution:

1. **No quiet drops.** Every item in the coverage matrix above has BLOCK or DEFER. If implementation runs into trouble on a BLOCK item, the controller (Claude) must **escalate to John** with options — not silently downgrade or defer.

2. **Coverage matrix re-checked at plan handoff.** When the implementation plan is written from this spec, every BLOCK item must map to one or more concrete plan tasks. The plan controller verifies this mapping before execution begins.

3. **Coverage matrix re-checked at implementation handoff.** When subagents execute plan tasks, the controller verifies (after each phase) that the actually-shipped code covers the spec's acceptance criteria. No phase is "done" without this audit.

4. **DEFER stamps required for any V2.x reference.** "We'll get to it later" is no longer acceptable shorthand. If something is deferred, it goes to a real `docs/superpowers/v2.x-scope.md` (or similar) with an explicit John-approved DEFER stamp.

5. **Polish passes audit against original spec.** If 1.8.1 grows a "polish" or "cleanup" sub-task, it audits against the original ascendant of every surface it modifies. No more "removed ScenarioBuilderView and lost the appreciated stock donation input" failures.
